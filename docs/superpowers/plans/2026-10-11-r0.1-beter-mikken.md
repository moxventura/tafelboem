# R0.1 "Beter mikken" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what R0 playtest 1 found, so the kids see every consequence of their answers, "?" is
only pressed on purpose, and the answer log can measure whether a HUD correction sticks.

**Architecture:** The server stays authoritative. Learning logic (re-ask accuracy, mis-clicks, the
yeet picker) goes in the pure-Java `core` package with JUnit tests. The session engine gains a
"feedback" outcome that releases the player and sends the correction to a new client HUD element.
Camera assist is a client tick handler driven by a small new payload. Bomb looks, the yeet
variants and the world setup command are Minecraft-side changes checked with GameTests and the
client playthrough screenshots.

**Tech Stack:** Java 25, Fabric Loader 0.19.5, Fabric API 0.161.0+26.2 (`HudElementRegistry`,
`ClientTickEvents`, networking), Minecraft 26.2 (unobfuscated names), JUnit 6, Fabric GameTests and
client GameTests, Python + Pillow for textures.

**Spec:** `docs/superpowers/specs/2026-10-07-tafelboem-design.md`, section *R0.1 "Beter mikken"
(detailed scope)*. Findings P1–P11 are in `docs/evaluations/R0.md`.

## Global Constraints

- The `core` package imports nothing from `net.minecraft`, `com.mojang` or `net.fabricmc`
  (enforced by `CoreArchitectureTest`).
- Every user-facing string exists in both `en_us.json` and `nl_nl.json` with the same arguments
  (enforced by `LanguageFilesTest`).
- The villain never states a wrong fact and never comments on the child's ability.
- A correct answer never hurts the child; a sibling is never hurt by someone else's bomb.
- Every new feature has a config toggle (definition of done).
- Vanilla look: no new colours on the question screen, only vanilla buttons.
- Commits use the repo-local identity; every commit ends with the `Co-Authored-By` line.
- Version becomes `0.1.1`; the release is tagged `r0.1`.

  fields)

```java
	@Test
	void aMissedFactAnsweredRightWhenItComesBackCountsAsAGoodReask() {
		StatsReport report = StatsReport.of(List.of(
				answer(7, 8, false, 5000),
				answer(2, 3, true, 2000),
				answer(7, 8, true, 4000),     // re-ask, right
				answer(6, 9, false, 5000),
				answer(1, 1, true, 1000),
				answer(6, 9, false, 6000)));  // re-ask, wrong
		assertEquals(new StatsReport.ReaskStats(2, 1), report.reasks());
	}

	@Test
	void aFactThatComesBackMuchLaterIsNotAReask() {
		List<AnswerRecord> answers = new ArrayList<>();
		answers.add(answer(7, 8, false, 5000));
		for (int i = 0; i < 6; i++) {
			answers.add(answer(2, 2, true, 1000));
		}
		answers.add(answer(7, 8, true, 3000));
		assertEquals(new StatsReport.ReaskStats(0, 0), StatsReport.of(answers).reasks());
	}

	@Test
	void questionMarkWithDigitsTypedIsALikelyMisclick() {
		StatsReport report = StatsReport.of(List.of(
				dontKnow(7, 8, 2),
				dontKnow(6, 7, 0),
				dontKnow(3, 4, 1)));
		assertEquals(2, report.likelyMisclicks());
	}
```

- [ ] **Step 2: Run** — compile failure.
- [ ] **Step 3: Implement.** `reasks()` walks the answers in order with a map `Fact → index of the
  miss`. An answer whose exact fact is pending and comes within `REASK_WINDOW = 5` answers of the
  miss counts as a re-ask (correct when `outcome == CORRECT`) and clears the entry; a miss then
  (re)registers its fact. `likelyMisclicks()` counts `DONT_KNOW` records with `typedDigits > 0`.
  Old log lines have no `via`/`typedDigits`, so Gson gives `null`/`0`: they count as "not a
  mis-click", which is the safe default.
- [ ] **Step 4: Thread the input details through.** `QuizC2S` gets `via`; `SessionManager`
  passes `via` and (for `DONT_KNOW`) `value` as typed digits into `Learners.record(..., String via, int typedDigits)`.
- [ ] **Step 5: Show them in `/tafelboem stats`** with two new keys:
  - `tafelboem.stats.reasks`: "Opnieuw gevraagd na een fout: %s van %s goed (%s%%)" /
    "Asked again after a miss: %s of %s right (%s%%)"
  - `tafelboem.stats.misclicks`: "Waarschijnlijk per ongeluk op ? gedrukt: %s" /
    "Probably pressed ? by accident: %s"
- [ ] **Step 6: Run** `./gradlew test` — PASS. **Commit.**
