## 4. Playtest 1 findings

The cause of each finding was checked in the code on 2026-10-11.

| # | What we saw | Cause | Type |
|---|---|---|---|
| P1 | The yeet was a big success, and the spinning was hilarious. | `GraafFout.yeet` plus the server-side spin. | ✅ Keep and expand |
| P2 | The OK button is too small, and the kids sometimes pressed "Ik weet het niet" because it was more visible. | OK is a 20×20 key in the bottom-right corner of the pad (`QuestionScreen.java:130`). The "?" button is at least 70 px wide and sits in the same row, directly next to it (`QuestionScreen.java:137`). The biggest target is exactly where a child reaches for OK. | 🚫 UX blocker, and it pollutes the data |
| P3 | After a wrong answer or "?", the correct answer shows but the penalty plays behind the screen, so nobody sees it. | `SessionManager.miss()` plays the penalty and opens the correction screen in the same tick (`SessionManager.java:150` and `:170`). | 🚫 UX blocker |
| P4 | They want an easy way to set the difficulty. | R0 has no levels. The plan has levels 1–9 that unlock one by one through a lobby bell (R1/R3). | 💡 Wish |
| P5 | Idea: a wrong answer gives Graaf Fout some life back. | New. | 💡 Wish |
| P6 | They tried to dodge thrown TNT and couldn't. | Two things make dodging impossible. The throw aims at where the player stands *at throw time* (`BossFight.throwNextBomb`). On landing, the question starts for the target wherever they are and roots them on the spot (`BossFight.java:190`). | 💡 Wish, plus an unmet expectation |
| P7 | "When does he throw different bombs?" It looked like only firecrackers. | He already throws Gewone TNT every 3rd throw (`BossFight.java:153`), but the difference can't be seen. Knalletje and Gewone TNT are both mostly the same red; only the yellow or white accents differ. In a fight, the kicked bomb always makes the same small 1.5 blast (`BossFight.java:249`) and the same yeet, whatever the bomb. The tier's penalty is hidden by P3. | 🐞 Design defect |
| P8 | After being hit, they sometimes couldn't see Graaf Fout and missed the yeet, even though they answered correctly. | The camera is never touched. The player stays rooted facing wherever they were looking. | 🚫 UX blocker for the main reward |
| P9 | It's possible to run away. | There is no boundary; he only targets players within the arena radius (`BossFight.java:309`). | ✅ Accepted for now |
| P10 | Idea: a Kippenbom whose chickens explode once more into more chickens. | New. | 💡 Wish |
| P11 | They didn't like the creative superflat world (slimes, day/night cycle). Consider premade levels (`.slime`) and a server-style world selection. | R0 relies on a world you create yourself. | 💡 Wish, plus a setup issue |

**Data quality.** Every mis-clicked "?" (P2) is logged as `DONT_KNOW`. The picker treats it as a
miss and re-asks a fact the child knew. This makes the "?" count useless as a measure of honest
uncertainty, and it adds noise to the log the R2 learning model will be tuned on. After P2 is
fixed, mis-clicks can be estimated from the log: a "?" pressed very quickly while digits were
already typed is suspect.

**About `.slime`.** The Slime Region Format comes from Hypixel. Its main implementation, Advanced
Slime Paper, is a Paper server fork that runs plugins only, not Fabric mods, and no Fabric loader
for the format turned up. The Fabric-native ways to get the same result (fast, premade, resettable
levels) are listed under section 6.

**Decision (2026-10-11):** go, with patch release R0.1 first.

The core hypothesis has qualitative support:
- The yeet was the highlight.
- The kids asked for more: difficulty, different bombs, new mechanics.
- The feedback doesn't mention the pivot trigger (the question pop-up feeling like an
  interruption).

Three UX blockers stopped the kids from seeing the consequence of their answers: P2, P3 and P8.
They are fixed in R0.1 and played again before R1 builds on top of them. The missing numbers are
collected with R0.1.

## 6. Backlog changes

  - The question screen stays in vanilla Minecraft style: no big green button, just a wide vanilla

  - P3 is solved by dropping the retype: the question screen closes, the kid is free, the penalty
    plays, and the correct fact shows on the HUD while the game goes on. The re-ask is the check,
    measured as re-ask accuracy. The retype stays behind a toggle. The reasoning is in the spec,

### R0.1 "Beter mikken" (patch, then playtest 2)

Hypothesis: with the blockers fixed, the kids see every consequence of their answers, and "?" is
only pressed on purpose.

The final scope and acceptance criteria are in the spec, under *R0.1 "Beter mikken" (detailed
scope)*. The P11 quick fix became a small `/tafelboem arena` command instead of a hand-made world,
so it also works in the kids' existing worlds.

### Release order

| Release | Content | Change |
|---|---|---|
| R0.1 "Beter mikken" | The patch above | New |
| R1 "Kies je level" | Level select in a small hub (easy, medium, hard → band, bombs, HP); premade arena from structure templates; yeet catalogue; tier-specific bombs per level; recursive Kippenbom. Moving the learning model back loses no data. The answer log has recorded every answer since R0,
so the R2 model can be replayed and tuned on real history.

### Guardrails for the kids' ideas

- **P5, heal on wrong.**
  - Story: Graaf Fout loves mistakes, so he *eats* the wrong answer.
  - Only a wrong answer heals. "?" and ESC never do: *"Hè, geen fout om op te eten!"* This makes
    "?" better than guessing, which is exactly what the "?" button is for.
  - Small: one hit back, at most 3 times per fight, never above full health.
  - Before it ships, the pacing test checks that a 60%-accurate child still wins.
- **P6, dodging.**
  - A dodged bomb lies on the ground with a visible fuse.
  - Running into it starts the question as before.
  - If the fuse runs out, it pops harmlessly: soot puff, no question, no damage to him.
  - Damage only comes from answered kicks, so dodging never replaces sums. Watch answers per minute
    in playtest 3.
- **P10, chicken bomb.** At most 2 generations, and the existing spectacle cap and cleanup apply.
  Make it count: *a* chickens each burst into *b* chickens, so 3 × 4 shows as 12 chickens in
  3 groups.
- **P11, premade levels.** Fabric-native options, in order of effort:
  1. A premade world save in the Prism instance export.
  2. Arenas built in-game, saved as vanilla structure templates (`.nbt`), and placed by the mod in
     a void world. Re-placing the template after a fight resets the arena.
  3. A hub with a door per level (server-style selection). Optionally later, a Fabric dedicated
     server on the NAS, so there is one log and one world for all PCs.
